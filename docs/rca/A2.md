# A2 — Enquête B4 : le code promo zombie

## Symptôme observé

Avec `SEED_BUGS=true`, le code promo `EXPIRED` est accepté. Le test UI n'affiche pas l'erreur attendue et l'utilisateur arrive à l'écran de paiement. Le test API attend HTTP 400, mais reçoit HTTP 201.

## Impact

La remise de 15 % peut être appliquée après expiration. Le parcours UI suggère en outre à l'utilisateur que la réservation est valide.

## Preuves de l'enquête

- **Configuration :** `GET /api/config` a retourné `seed_bugs: true`.
- **Test UI :** `test_expired_promo_code_shows_error` a échoué de la même façon lors de trois exécutions. À la ligne 50 de [test_booking_ui.py](../../qa/tests/ui/playwright/test_booking_ui.py), le test saisit `EXPIRED`; à la ligne 52, il attend `Promo code expired`, mais l'utilisateur arrive au paiement.
- **Test API :** [test_booking_rules.py](../../qa/tests/api/test_booking_rules.py:23) échoue pour `[EXPIRED]`, car le statut reçu est 201 au lieu du 400 attendu.
- **Base :** `EXPIRED` a une remise de 15 % et une expiration au `2026-11-11 12:21:02.399541`; la requête SQL confirme `expires_at < NOW()`.
- **Trace locale :** `qa/reports/a2-b4/trace.zip` (ignoré par Git, car il contient l'en-tête `Authorization`) confirme la saisie `EXPIRED`, puis `POST /api/orders` en 201. Extrait des corps de requête et de réponse, en-têtes retirés :

  ```text
  Requête : {"event_id":85,"items":[{"category_id":254,"quantity":1}],"promo_code":"EXPIRED"}
  Réponse : {"id":108,"event_id":85,"status":"pending","total_cents":2975,"created_at":"2026-11-24T11:06:09.426512Z","expires_at":"2026-11-24T11:16:09.427726Z","items":[{"category_id":254,"quantity":1,"unit_price_cents":3500}]}
  ```

  L'écran atteint est l'écran de paiement ([capture extraite de la trace](./B4-trace-paiement.jpg)). Aucun événement de console de niveau erreur n'est présent.
- **Code :** la condition d'expiration est à la ligne 34 de [orders.py](../../backend/app/routers/orders.py:34). Le diagnostic et la RCA détaillés sont dans [B4.md](./B4.md).

## Conclusion

Le défaut B4 vient du garde `and not settings.seed_bugs` : lorsque le mode bugs est actif, le refus d'un code expiré est contourné. La trace confirme que l'API accepte la commande et que le frontend poursuit le parcours.
